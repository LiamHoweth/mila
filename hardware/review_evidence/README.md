# MiLa passive bypass bench revision A — evidence guide

Start with `docs/passive-bypass-design.md`. Its overview, exact contact and
interboard tables, operating envelope, first-power-up steps and remaining
application requirements describe the complete reference.

The carrier is under `hardware/passive_bypass_rev_a/`; the separate supervisor
is under `hardware/passive_bypass_supervisor_rev_a/`. Each has editable KiCad
source, project-local libraries, BOM, native netlist and fabrication outputs.
The supervisor also has the exact external switch BOM and terminal wiring.
These connectors do not share the original motherboard/module pinout.

## Evidence interpretation

- Host suite: 4 retained CAN payload tests, 41 new behavior-model tests,
  3 carrier CAD/source tests and 12 independent supervisor-netlist tests.
  The latter include 512 settled Boolean combinations and loaded-drive
  resistor-corner calculations. The total is 60 tests.
- `software-validation-final.json` and `host-tests-final.txt` record actual
  host execution. `connectivity_audit.json` records the independent retained
  PCB mapping comparison and historical source preservation check.
- `carrier-erc-final.json` / `supervisor-erc-final.json` are native schematic
  checks. Final PCB reports include connectivity and schematic parity, using
  the projects' recorded KiCad rules. Read those reports and their ignored
  default checks rather than treating “zero violations” as universal coverage.
- `original_source_hashes.json` inventories ten retained original KiCad
  source/library files. The original files are never regenerated by the new
  board generators.
- `docs/passive-bypass-validation.csv` has 34 physical procedures, all
  `NOT_RUN`. Supervisor `bench_expectations.csv` has 33 focused probes, all
  `PENDING`. These are overlapping acceptance plans, not 67 measured results.

No physical relay, ECU, actuator, vehicle, environmental, endurance or
power-sequencing acceptance result was obtained. There is no SPICE waveform
claim or certified component-fault coverage. Release/bounce, arbitrary supply
ramps and wrong-but-live DAC commands are not proved by a Boolean model.

## Reproduce

Use Python 3 for host checks:

```sh
python3 -m unittest discover -s tests -q
python3 tools/check_passive_bypass_design.py
python3 tools/build_passive_bypass_supervisor.py --verify-netlist hardware/passive_bypass_supervisor_rev_a/netlist.xml
```

KiCad 10 and its bundled Python/wx/pcbnew runtime regenerate and check the
boards. The carrier generator and supervisor PCB generator require that
runtime. The supervisor schematic generator uses ordinary Python. Exact
commands and native rule reports are retained alongside each board. Running
the schematic generator does not regenerate the supervisor PCB; run its PCB
generator afterward and repeat native parity/DRC checks.

Build this revision only for the specified isolated, current-limited 0–5 V,
≤1 mA simulator. K7/K8 function, the vehicle's required physical state and
allowed signal disturbance are unresolved application requirements.
