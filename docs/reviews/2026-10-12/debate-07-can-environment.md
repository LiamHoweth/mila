# Debate 07 — CAN/openpilot versus vehicle environment

2026-10-12. Actual exchange between specialists `/root/can` and `/root/environment`, after independent memos 12/15. Outcome: accepted scope corrections; **isolated bench only**, vehicle integration **NO**. No physical CAN traffic, source modification or new physical evidence.

**CAN challenge:** Native CAN might avoid analog steering substitution, but current upstream LEAF support is 2018–23 with ProPILOT and its controller generates steering/cancel/HUD, not independent acceleration/braking. Unknown target identity and research requirements prevent recommending wholesale analog removal. More urgently, the diagnostic's external builds enter Normal mode before ARM; software STOP only clears `armed`, without hardware queue abort. Does environmental analysis accept that disarmed operation is not passive capture and physical stop latency remains unproven?

**Environment response:** Accepted both corrections. Normal mode electrically participates through ACK/error signaling; removing future enqueue permission does not establish physical bus silence. Native CAN removes analog steering hazards only if actual identity/harness and steering/stock-ACC objective match. It does not qualify retained custom boards/ESP nodes or establish Nissan longitudinal control.

**Accepted correction from environment:** CAN specialist accepted that every retained interface still requires its actual supply, logic/common-mode/fault envelope, topology/termination, grounds, mounting and permitted functional degradation to be specified. EMI/ESD and fault-response evidence remain necessary even if analog steering is omitted. A regulated power source alone cannot establish signal-interface robustness. Exact environmental profiles and levels are UNKNOWN.

**Resolution experiment proposed, not performed:** Build an isolated, correctly terminated CAN fixture with identified oscillator/transceiver and contained supplies. Use bus analyzer plus TXD/bus waveform capture. First compare disarmed Normal-mode ACK/error participation at correct bitrate and deliberate mismatch, separate from application frames. Then arm the bench heartbeat and record last physical application frame against STOP, jumper removal and timeout during missing ACK, arbitration loss and reconnect. Establish a measured stop bound; a queued/retrying frame is presently an analytical possibility, not an observed event. Verify an independently configured silent receive-only mode before any future vehicle observation. Stop for unexpected current, ratings violation, uncontrolled traffic or unintended restart.

**Evidence:** `firmware/comma4_can_bench/src/main.cpp:83–108,122–126,184–196,263–271`; [MCP2515 DS20001801K](https://ww1.microchip.com/downloads/aemDocuments/documents/APID/ProductDocuments/DataSheets/MCP2515-Family-Data-Sheet-DS20001801K.pdf), §§10.3/10.5, pp.59–60; pinned [Nissan controller](https://github.com/commaai/opendbc/blob/390618eef8be4462aebdfddb534d289b23684a23/opendbc/car/nissan/carcontroller.py) and [configuration](https://github.com/commaai/opendbc/blob/390618eef8be4462aebdfddb534d289b23684a23/opendbc/car/nissan/values.py); memo15's bench/vehicle environmental distinction.

**Remaining dissent:** none on these bounded claims. Vehicle applicability, installed software, exact electrical/environmental acceptance limits and physical stop behavior remain unresolved; agreement is not validation.
