# 11 — Embedded firmware independent review

Verdict: **PROTOTYPE FIRST**, conditional on a new guarded simulator controller. No existing firmware is compatible with this supervisor; no vehicle advancement. Review date: 2026-10-12. Source inspection and a read-only raw-PCB pad extraction were performed; no flashing, builds or physical tests.

## Ranked findings

1. **Automatic engagement and reversed request convention — CONFIRMED SOURCE.** `/Users/howeth/Downloads/FabriceBoard_PID_AutoSweep(1).ino:37–45,138–141,239–257,297–298` waits 15 seconds, then gangs GPIO15/4/0 active LOW with no mandatory enable. Its initialization drives these pins HIGH (`:200`), whereas the new carrier requests are active HIGH (`hardware/passive_bypass_rev_a/pin_net_map.csv`, Q1–Q4 gate networks). Blind pin reuse therefore inverts intent. Neither READY nor WDI is implemented. Hardware may prevent arming with requests HIGH, but that is not a working integration. Preserve this sketch solely as reference.

2. **Successful boot discovery can mask failed later DAC writes — CONFIRMED SOURCE / ANALYTICAL INFERENCE.** Sketch `:111–135,204–207` records `begin()` once and discards every `setChannelValue()` result. The sweep engages even with a missing DAC; a subsequent I2C fault can leave an earlier output retained while requests continue. Relays are engaged before that iteration's writes (`:297–298`). READY must require validated initialization, each required write acknowledgment and measured output acceptance. An ACK proves transport acceptance, not analog accuracy or semantic correctness.

3. **100 Hz application frequency is not a valid heartbeat contract — CONFIRMED SOURCE.** Sketch `:62,233–236` nominally iterates every 10 ms and has no deadline-failure branch. The supervisor README `:78` specifies a possible lower watchdog bound of 10.35 ms. Feeding once every 10 ms could trip a conforming part. Use its proposed 30 ms falling-edge cadence, with a 1 ms HIGH pulse, only after three completed, validated 10 ms iterations. Never feed from an independent timer/ISR that survives a hung control loop. A stale-but-valid command remains undetected by timing alone.

4. **Pin numbering and functional routing are unresolved — CONFIRMED SOURCE / UNKNOWN.** Original `PCB1.2.kicad_sch` J3 is a generic counter-clockwise 2×19 connector with `ESP32:ESP-32` footprint, not a GPIO-labeled contract. Raw `PCB1.2.kicad_pcb` extraction confirms J3-23→J4-4, while J4-23→J7-26…31 is separate; J3-25/26→J7-32/33. J6-11/10 have singleton unconnected nets. Assigning GPIO15 to J3-23 or the sketch's brake A/B channels to J6 remains conditional on physical board and I2C-bus identity. Espressif's [WROOM-32D/U datasheet](https://documentation.espressif.com/esp32-wroom-32d_esp32-wroom-32u_datasheet_en.html), §§2–3, pp.9–14, identifies GPIO0/2/5/12/15 reset straps; a module's pin numbers cannot establish a development board's header ordering. Verify continuity and strap loads before selecting requests/READY/WDI GPIOs.

5. **No external command freshness or independent-domain policy — CONFIRMED SOURCE.** The sketch reads no serial commands (`:301–309`) and gangs three controls (`:138–141`). It cannot implement bounded host intent, replay rejection, host-loss shutdown or permitted K7/K8 state transitions. The separate CAN diagnostic's 2 Hz `0x5A5` heartbeat (`firmware/comma4_can_bench/include/can_config.h`) exceeds the supervisor's 125.4 ms maximum interval and proves no DBW control-cycle validity.

## Minimum controller and decisive tests

PROPOSED CHANGE: a separate bench-only state machine: BYPASS → source/rail/output validation → READY and qualified WDI → physical zero-request ARM → short explicit request → latched FAULT/BYPASS. Use three distinct domain outputs; exclude PID, autonomous sweeps, vehicle CAN and automatic resume. Version and sequence commands, bound their lifetime, fail LOW on deadline/write/freshness errors, and require manual requalification. Set numerical deadlines from fixture measurements before powering.

Scope boot/reset requests, READY, WDI, ARMED, permission, coil current and COM outputs. Inject I2C NACK/stall, host silence/replay, missed iterations and an intentionally wrong but ACKed DAC value. Kill advancement on any unattended engagement, resumed request after recognized fault, missing STOP effect, or false health after injected validation failure. UNKNOWN: exact GPIO manifest, timing under library stalls, independent analog feedback, application limits and physical transfer behavior.
