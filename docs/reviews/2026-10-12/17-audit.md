# 17 — Codex and evidence audit

**Verdict: PROTOTYPE FIRST, isolated bench investigation only.** Codex can maintain the CAD/model/firmware evidence, but a person with instruments must establish physical behavior. No shared checks were rerun by this specialist. Source inspection: 2026-10-12; recorded results below remain October 7 results pending coordinator verification.

1. **Physical acceptance is entirely missing. CONFIRMED SOURCE.** `hardware/review_evidence/validation-summary-final.json` reports zero physical results; `docs/passive-bypass-validation.csv` has 34 NOT_RUN procedures and supervisor `bench_expectations.csv` has 33 overlapping PENDING probes. Trigger: advancing because “60 tests / zero violations” passed. Consequence: unknown coil-current decay, signal transfer, partial-power behavior and contact failures receive undeserved credit. Proposed change: label every claim by evidence class and keep completed physical validation unchanged when scoring the improved proposal.

2. **Routing acceptance guards can be bypassed or detached from the checked board. CONFIRMED SOURCE / ANALYTICAL INFERENCE.** `tools/build_passive_bypass_supervisor_board.py:107–136` uses `assert` for clean-report checks and circuit/footprint hashes; lines 663/675 also protect concurrent-source stability with assertions. Python optimization removes assertions ([Python language reference §7.3](https://docs.python.org/3/reference/simple_stmts.html#the-assert-statement)). Additionally, `capture_accepted_layout()` reads existing clean reports before loading the current PCB; it does not bind those reports to that PCB's digest. Trigger: optimized execution, or a changed PCB followed by capture without fresh checks. Consequence: an “accepted” snapshot can lack its claimed validation provenance. This does not show the existing accepted layout is wrong. Proposed change: explicit failing checks and input/output digest binding before future capture/release.

3. **Good independent oracles still have finite scope. CONFIRMED SOURCE.** Supervisor tests intentionally evaluate exported XML rather than importing the generator (`tests/test_passive_bypass_supervisor_cad.py:1–18`); carrier mapping and ten historical hashes have separate checks (`tools/check_passive_bypass_design.py:193–201`). However, the XML is a stored artifact, RC/Schmitt delay becomes identity after settling (supervisor test lines 104–107), and power-loss timing is user-supplied (`tools/passive_bypass_model.py:323–340`). Trigger: stale exports or asynchronous reset/clock/rail transitions. Consequence: Boolean pass results cannot establish native-source freshness, reset recovery timing or analog margins. Require fresh native export, parity and version/input hashes for each evidence bundle.

4. **A correct watchdog cannot prove a correct command. CONFIRMED SOURCE.** Model lines 1–7 assume READY semantics; lines 132–137 separate heartbeat validity from command validity. Trigger: fresh heartbeat with stale/wrong DAC values and falsely asserted READY. Consequence: the model can permit actuation while outputs are unsuitable. Required experiment: inject wrong-but-live outputs and separately freeze command refresh while maintaining heartbeat; record who detects each fault and whether permission actually falls. Do not score this as independent analog fault coverage.

5. **Some “validation” commands mutate evidence. CONFIRMED SOURCE.** Checker main writes `connectivity_audit.json` (lines 203–204); supervisor `--validate-existing` rewrites hashes and invokes export validation (lines 657–659). Trigger: parallel auditors use them casually. Consequence: historical/current records can be mixed. Existing ZIP includes generators, tests and `SHA256_MANIFEST.json`; its presence was inspected, not hash-verified here. Proposed change: coordinator-owned dated outputs and immutable release copies, with one CAD integrator.

**Required meaningful checks:** reject circuit/footprint mutations under normal and optimized Python; reject stale-report capture against a changed board; reproduce extracted-package checks and manifest verification in a disposable location; measure V08–V10, V17, V29, V31–V33 with raw traces, actual assembly identity, instrument settings and unrounded worst-case timing. Application limits remain UNKNOWN.

**Ownership / stop criteria:** exclusive CAD/generator ownership; separate model, firmware and documentation owners; one person coordinates wiring and physical tests. Stop release advancement if exact assembly cannot be traced to CAD/BOM/export hashes, measurements violate component limits, or a fault automatically reengages outputs contrary to the stated contract. Vehicle integration remains blocked independently of software/CAD scores.
